# 上财自动滑块 (sufe-auto-slider)

检测到**上海财经大学统一认证登录页**（`login.sufe.edu.cn`，或任意 `*.sufe.edu.cn/login`——含 WebVPN 代理域名，如 `newapi-sufe-edu-cn-s.webvpn.sufe.edu.cn`）时，自动完成「滑块验证 + 登录」，成功后自动跳回原业务系统。

> 仅供本人账号的个人自动化使用。请控制请求频率，遵守学校相关规定；请勿用于他人账号或任何高频、批量场景。

## 功能特性

- 自动检测上财登录页（SPA 渲染完成后触发）；默认「**点击页面登录按钮触发**」：你点击页面上的「登录」按钮（或表单内回车）时才接管——拦截页面原生流程，改为扩展自动过滑块并登录；弹窗可切换为「倒计时自动」（2 秒后自动登录，点击/打字即取消；只认 pointerdown/input，关闭浏览器翻译弹窗等只会引起 focusin 的场景不会误取消）
- **凭据以页面输入框为准**：两个输入框都有值（浏览器密码管理器已填充，或你手动填好）→ 直接采用、不覆盖；为空 → 把扩展保存的学号密码自动填入登录框再登录。密码可以只交给浏览器保存，扩展里不存也能用
- **验证码默认「字符」（图片验证码）**：内置纯 JS OCR（轻量 CNN + 4 位置分类头，约 7.2 万参数，单张推理**约 0.12 秒**）识别 4 位字符；**概率决策**——置信度 <85% 时先换图重识别（最多 3 次，不占提交轮次），0/o 等形近字在置信区间内按先验分配。实测单次提交命中 8/10 = 80%，**E[T] ≈ (0.12s OCR + 0.25s 网络) / 80% ≈ 0.5s**；如遇滑块，在弹窗「验证码方式」切到「滑块（拼图）」
- **缺口定位：经典分割严格优先，CNN 兜底**——缺口模板在图中恒为 ~96×93、面积 ~5590（382 张实测 99% 一致），「形状/面积合规且全场唯一」的平坦纯白连通块即可信（本地仅 **~2ms**、误差 0px）；不可信时才懒加载整图 CNN（4×[Conv3x3+ReLU → 高度方向 MaxPool] → 1×1 → 256 列 softmax → soft-argmax，4.9 万参数，纯 JS）
- CNN 训练数据为真实验证码 + 精确分割标注；输入为整图 area-resize 到 256×128，回归「可通过窗口中心」（该模型同时是渲染变化时的兜底）
- 服务端**容差实测**：可通过窗口恒为 5 个连续整数（中心 = 缺口左缘 − 3，两侧各 ±2px）；预测值四舍五入即 X，先试 0/±1/±2 即覆盖全部余量
- 三级兜底：CNN → CNN 邻域 → 经典「平坦纯白连通块」分割及邻域 → 历史盲试候选；失败不作废 token，同一 token 内连续校验，通常**首探测一次通过**
- 密码使用服务端下发的 RSA 公钥（PKCS#1 v1.5）加密后传输——浏览器 WebCrypto 不支持 v1.5 填充，扩展内置了一个无依赖的 BigInt 实现（`sufe-crypto.js`）
- 浮窗滚动显示每轮滑块尝试结果（含识别方式/CNN 置信度/分割坐标）；弹窗提供「登录」（当前页直接执行，页面未注入脚本时自动注入、免刷新）与「测试滑块」（不提交账号）、密码显隐、历史首探命中率统计
- 闭环自检：在任意支持的登录页 URL 后加 `#sufe-test-slider`（如 `login.sufe.edu.cn/login/#sufe-test-slider`）只跑滑块验证并在浮窗显示结果，不触碰账号密码
- 密码仅保存在本机 `chrome.storage.local`，不上传、不进浏览器同步；扩展只向登录页**自身域名**提交数据（同源，经 WebVPN 时即走代理域名）
- 登录成功后 20 秒内不重复触发（防跳转异常导致自动登录死循环）

## 安装（开发者模式加载）

1. 打开 Chrome，地址栏输入 `chrome://extensions/`
2. 右上角打开「**开发者模式**」
3. 点左上角「**加载已解压的扩展程序**」，选择本仓库克隆下来的 `sufe-auto-slider` 文件夹（或从 [Releases](https://github.com/haohaoo3o/sufe-auto-slider/releases) 下载最新 `sufe-auto-slider-vX.Y.Z.zip` 解压后选择该文件夹）
4. 点击工具栏扩展图标，填写学号、密码，勾选自动登录，点「保存」

日常无需任何操作：被业务系统跳到登录页时会自动处理并跳回。

## 工作原理

```
① GET  /api/v3/auth/queryAllValid        → RSA 公钥 + publicKeyId + loginTicket
② POST /api/v3/sliderCaptcha/init        → 背景图 sourceImage + 滑块图 newImage + Y + token
③ CNN  整图 → area-resize 256x128 → conv/pool → soft-argmax → 可通过窗口中心 X
④ GET  /api/v3/sliderCaptcha/check       → X/Y/token 校验，通过得 vcode（失败 token 仍可用，可换候选重试）
⑤ POST /api/v3/auth/doLogin              → 学号 + RSA 加密密码 + vcode → 会话 Cookie
```

X 坐标约定来自登录页前端源码：`X = 拖动左偏移(显示px) × imgScale`，`imgScale = 背景图自然宽 / 显示宽`，
故 X 为**背景图自然像素**坐标；背景图尺寸随机（宽 460–594、高 252–360），整图缩放到固定 256×128 后推理，输出再按宽度比例换算回原图。

**可通过窗口（实测）**：以「缺口左缘」为基准，服务端只接受 `左缘−5 … 左缘−1` 共 5 个整数（即中心 = 左缘−3、半径 ±2）。
模型直接回归窗口中心，四舍五入即命中；即使预测偏 ±2px 仍在窗口内。
（2026-10 验证码模板微调为 98×95/面积 6047，白洞左缘测量基准随之右移 1px，窗口实测变为 `左缘−4 … 左缘`；严格分割输出已落在新窗口中心。）

**图片验证码模式（默认）**：`GET /api/v1/image/getRandcode` 拉图 → 内置纯 JS OCR（轻量 CNN + 4 位置分类头，输入 128×48 灰度，72.2k 参数，BN 已折叠进卷积）识别 4 位字符
→ 随 `doLogin` 的 `dataField.vcode` 提交。验证码**不区分大小写**（实测：大写码用小写提交可通过）、
**每次提交只认一次**（错码即作废，需换图），故 `SSO10023`（验证码错误）时自动换图重试。
实测：3986 张样本训练（数据在 2000 张后饱和）；留出集整串 73–77%/字符 92–93%；27 张人工黄金集 81%；服务端真实接口提交 10 次命中 8（80%）。
**概率决策**：OCR 输出每个字符位置的 softmax 概率，联合置信度 <0.85 时先换图重识别（最多 3 次），避免在大概率失败的图上浪费提交；0/o 形近字在概率差 ≤0.12 时按字符先验（`0` 明显多于 `o`）取 `0`（离线测量增益不可见，保守保留）。
选型按「**期望通过时间**」：`E[T] = (OCR 耗时 + 网络耗时) / 单次命中率`。当前 `E[T] ≈ (0.12 + 0.25) / 0.80 ≈ 0.5s`；模拟表明更激进的置信门控（≥0.95）反而更慢——OCR 变快后提交成本占比上升。轻量版（w16）比标准版（w24）快约 2.5 倍、黄金集还高 3pp（81% vs 78%），故出货用轻量版；160×64 高分辨率版黄金集同 81% 但推理翻倍，未采用。
该模式为默认；如需滑块（拼图），在弹窗把「验证码方式」切到「滑块」。

登录成功后优先读取 `doLogin` 响应中的跳转地址，否则重载当前 URL 由 SSO 续跳（保留 service 参数）。

## 模型与训练（`lab/` 目录，随仓库提供，不进扩展包）

- 采集：`harvest2.py` 拉取真实验证码，整图存 `samples/full/`，并用「缺口 = 平坦纯白连通块」给出精确标签（`harvest.py` 为早期版本，存缺口横带）
- 训练：`train2.py`（整图输入 256×128、4 级 Y 池化、soft-argmax；numpy 手写 conv/pool/maxpoolY2 反向，仅依赖 numpy+PIL）；`cnn.py` 是层与反向实现，`resize.py` 是与 JS 等价的 area 缩放
- 校验：`gradcheck.py` 反向数值校验；`parity2.py` + `parity2.js` 校验 JS 与 numpy 前向逐样本一致；`live_eval2.py` 在线闭环评测（首探命中率/误差）
- 接口行为：`probe_tolerance.py` 实测可通过窗口与 token 语义（失败不作废 token）
- 打包：`build_dist.py` 生成 zip+crx；`release.py` 建 GitHub Release 并传附件

## 配置调整

轮数等常量集中在 `content.js` 顶部（`MAX_ROUNDS` / `BLIND_X` 等）；盲试候选仅在识别与分割都失败时使用。修改后在 `chrome://extensions` 中点扩展的「重新加载」即可生效。

## 排障

| 现象 | 处理 |
|---|---|
| 浮窗没出现 | 确认地址栏是 `login.sufe.edu.cn` 或 `*.sufe.edu.cn/login` 且页面已渲染出登录框（SPA 最长等待 20 秒） |
| 「学号或密码错误（SSO10002）」 | 在扩展弹窗中更正账号信息 |
| 浮窗显示方式=blind/多轮未通过 | 多为缺口样式变化或风控收紧期；用 `#sufe-test-slider` 自检页看 CNN/分割坐标是否合理 |
| 登录成功但页面没跳走 | 浮窗会提示，手动刷新或重新进入业务系统即可 |
